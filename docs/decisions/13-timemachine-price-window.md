# 13. 타임머신 시뮬레이터 — 가격 수집 기간

**날짜**: 2026-08-25

## 배경

타임머신 시뮬레이터(배당연습장 기획서 14장)는 3/10/20년 기간 선택지를
UI에 두고 있다. 그런데 `IngestionRunner`가 가격 수집 기간을
`endDate.minusYears(3)`으로 하드코딩해뒀다는 걸 구현 중에 발견했다 —
지금 57종목 유니버스도 전부 3년치 가격만 갖고 있어, 10년·20년 옵션은
계산 자체가 불가능한 상태였다.

`docs/decisions/01-data-source.md`는 Twelve Data 무료 플랜을 "6년까지
확인됨"으로 남겨뒀는데, 다시 읽어보니 이건 상한이 아니라 **6년을
요청해서 6년을 받은 것**뿐이었다 — 더 길게 요청했을 때 실제 상한이
어딘지는 그때 테스트하지 않았다.

## 검증

실제 프로덕션 키(`k8s/secret.yaml`의 `TWELVEDATA_TOKEN`)로 KO를 대상으로
직접 확인했다.

| 요청 기간 | 결과 |
|---|---|
| 10년 (`outputsize` 미지정, `start_date`/`end_date`만) | 2512건, 2016-08-25~2026-08-24 — 요청한 범위 그대로 전부 반환 |
| 20년 (`outputsize=5000`) | 5000건, 2006-10-06~2026-08-24 — 1회 호출당 5000행(≈19.8년) 상한에 걸림, 20년 요청 중 약 2개월만 누락 |
| `outputsize` 파라미터 없이 10년 요청 | 2512건, 동일 — 기존 `TwelveDataClient.fetchDailyTimeSeries(symbol, startDate, endDate)`가 이미 이 형태로 호출하고 있어 **클라이언트 코드 변경 없이도 그대로 동작** |

## 판단

- Twelve Data 무료 플랜은 일별 가격에 대해 연 단위 상한이 없고, 1회
  호출당 5000행(≈19.8년) 제한만 있다.
- 20년 전체가 필요한 경우 코카콜라 기준 약 2개월이 누락되지만, "20년
  재투자 시뮬레이션"이라는 기능의 성격상 무시 가능한 수준으로 판단해
  페이지네이션은 구현하지 않는다.
- `IngestionRunner`의 가격 수집 기간을 `--ingest.priceYears=N`(기본 3,
  기존 동작 유지)으로 인자화했다. 타임머신 브랜드 풀(8종목)은
  `--ingest.priceYears=20`으로 재수집한다.

## 남은 위험

- 브랜드 풀 종목 중 상장/배당 이력이 20년보다 짧은 경우(예: 신규
  브랜드)엔 자연히 더 짧은 기간만 채워진다 — 이건 실제 데이터 한계이지
  버그가 아니다. 서비스 계층이 요청 기간(`periodYears`)과 실제로 확보된
  기간을 비교해 "데이터 불완전"을 판정한다(CLAUDE.md — 조용히 넘어가지
  않는다).
- 기존 57종목 유니버스는 여전히 3년치만 갖고 있다. 이번 변경은 타임머신
  브랜드 풀에만 적용하며, 유니버스 전체를 20년으로 재수집할지는 별도
  판단이 필요하다(비용·시간 문제로 이번 범위 밖).
