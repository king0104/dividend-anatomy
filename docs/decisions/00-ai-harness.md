# 00. AI 하네스 — 도입한 것과 이유, 도입하지 않은 것과 이유

PROJECT.md 9장의 핵심 명제: "AI 도구 목록이 아니라, AI 산출물을 검증한 방법을
기록한다." 이 문서는 그 기록이다. 이 프로젝트에서 개발자가 내린 것이 아니라
Claude Code가 제안하고 개발자가 검토·확정한 결정들도 포함하며, 왜 그렇게
했는지를 남긴다.

## CLAUDE.md — 왜 이 규칙들인가 (2026-08-23)

CLAUDE.md는 초안을 Claude Code가 작성하고 사람이 검토하는 방식으로 만들었다
(PROJECT.md 9.B). 각 규칙의 근거는 아래와 같다.

| 규칙 | 왜 넣었나 |
|---|---|
| `BigDecimal`만 사용, `double`/`float` 금지 | PROJECT.md 8장이 이미 명시: 환율까지 곱해지는 돈 계산이라 부동소수점 오차가 실제로 드러남. ArchUnit으로 컴파일 시점에 강제해서 "AI가 관성적으로 double을 쓰는" 실패를 원천 차단 |
| 서비스 계층은 DB만 읽는다 | PROJECT.md 7장 아키텍처 원칙을 그대로 코드 규칙으로 옮김. 이번 세션에서 데이터 제공자를 Finnhub → Massive+Twelve Data로 여러 번 바꿨는데, 이 원칙 덕에 "서비스/계산 로직은 안 건드리고 어댑터만 교체"가 실제로 가능하다는 걸 데이터 소싱 검증 과정에서 직접 확인함 (`docs/decisions/01-data-source.md`) |
| 테스트 없는 계산 로직 추가 금지 | PROJECT.md 5.3: "AI가 거의 확실히 놓치는 지점"이라고 스스로 예고한 부분. 계산이 맞는지 판단할 유일한 수단이 테스트이므로, 테스트보다 코드가 먼저 나오는 걸 규칙으로 막음 |
| 투자 추천/판단/예측성 문구 금지 | PROJECT.md 2장의 비목표("종목 추천 안 함")를 코드/문구 생성 규칙으로 재확인. 계산 결과를 감싸는 설명 문장에서 AI가 슬쩍 "좋은 종목입니다" 같은 톤을 넣을 가능성을 사전에 차단 |
| 배당락일 T+1 규칙 | PROJECT.md 6장: 인터넷에 T+2 시절 규칙과 T+1 규칙이 섞여 있어 **AI가 옛 규칙으로 구현할 확률이 높다**고 프로젝트 스스로 예측해둔 지점. 가장 먼저, 가장 명시적으로 박아둬야 하는 규칙이라 CLAUDE.md 상단 근처에 배치 |
| 세금 상수명 분리(`US_WITHHOLDING_TAX_RATE`) | PROJECT.md 5.5: 미국 15%와 한국 15.4%가 숫자가 비슷해 혼동하기 쉬움. 상수명 자체로 방어 |
| 환율 시점 = 배당 지급일 기준 | PROJECT.md 5.6 그대로. 바뀌면 반드시 문서화하라는 조건도 그대로 옮김 |
| 특별배당은 정기 배당과 분리 | PROJECT.md 5.3: 이상치 제거. AI가 기본적으로 전부 합산해버리는 경향이 있다고 프로젝트가 미리 지적한 부분 |
| 시계열에 구멍이 있다는 전제로 짠다 / "가장 가까운 값" 조회 | PROJECT.md 5.4를 코드 규칙으로 구체화. 이번 세션의 데이터 소싱 검증(`docs/decisions/01-data-source.md`)에서 제공자마다 커버 기간이 다르다는 걸 실제로 겪었다 — Massive는 주가 2년, Twelve Data는 6년, Alpha Vantage 데모/무료는 배당 28년인데 주가는 4.7개월. "정확히 이 날짜"를 요구하는 코드는 제공자를 바꿀 때마다 깨지므로, 처음부터 근사 조회로 설계 |

## 데이터 소싱 관련 판단 — 왜 검증하고 왜 이렇게 결정했나

과정과 근거 전체는 `docs/decisions/01-data-source.md`에 있다. 요약하면:

- Finnhub(주력 후보였음) → 배당 이력·주가 시계열 모두 403으로 막혀 탈락
- Massive(구 Polygon.io) → 배당·분할은 무료로 충분(24년), 주가는 2년으로 조용히
  잘림(403이 아니라 200 + 축소 응답이라 더 위험한 실패 모드)
- Twelve Data → 주가는 6년으로 충분하지만, 무료 플랜은 **공개 배포 자체가 약관상
  금지**임을 확인
- Alpha Vantage → 데모 키로는 배당·분할·주가 전부 되는 것처럼 보였으나, 실제
  무료 키로 KO를 검증하니 주가는 무료로 4.7개월뿐(가장 나쁜 결과). 배당·분할은
  Massive보다 필드가 풍부해 우수
- Stooq → ToS를 보기도 전에 봇 차단 챌린지로 자동 접근 자체가 막혀 있어 제외
  (재배포 약관 문제보다 훨씬 명확한 "접근 통제 회피" 문제라 판단)

**최종 결정**: 배당·분할 = Massive, 주가 시계열 = Twelve Data.
**약관 확인은 의도적으로 프로젝트 완성 이후로 미뤘다** — Massive는 약관이
불명확하고, Twelve Data는 공개 배포가 이미 "안 된다"고 확인된 상태였음에도,
적발 확률과 결과(키 정지 수준, 소송 위험 거의 없음)를 실제로 따져보고
감수하기로 판단했다. 어댑터 격리 원칙(PROJECT.md 7장) 덕에 나중에 제공자를
교체해도 서비스·계산 로직은 그대로 둘 수 있다는 게 이 판단의 근거였다.

이건 "몰라서 그랬다"가 아니라 "알고도 리스크를 감수하기로 판단했다"는 걸
스스로 증명하기 위한 기록이다. 포트폴리오 질문("약관 확인 안 하셨어요?")에
대한 답이 이 문단이다.
