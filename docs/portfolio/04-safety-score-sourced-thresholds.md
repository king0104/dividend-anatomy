# 04. 배당 안전도 스코어 — 임의 임계값을 거부당하고 실제 근거를 찾은 과정

**날짜**: 2026-08-25
**관련 커밋**: `b1ca247`(배당 안전도 스코어 백엔드)
**관련 문서**: [14. 배당 안전도 스코어 계산 공식](../decisions/14-dividend-safety-score-formula.md)(전체 출처·조사 결과),
[12. 배당 안전도 스코어 데이터 소스](../decisions/12-dividend-safety-score-data-source.md)의 후속 작업

## 문제

기획서 1-7절은 5개 재무 지표(배당성향·FCF 대비 배당·ROE·부채비율·이자보상배율)를
"안전 30~60% / 위험 80~100%↑" 같은 정성적 구간으로만 제시했다. 이걸 0~100점
하나로 합산하는 구체적 공식은 기획서에 없어서, 처음엔 내가 그럴듯해 보이는
숫자로 선형보간 경계값을 채워 계획에 넣었다.

사용자가 이 계획을 승인하지 않고 명확히 되돌렸다: "임의로 정하지 말고, 진짜
좋은 배당주를 찾기 위해 필요한 지표들을 웹에서 찾아보고, 자주 사용하는
지표·실제로 중요한 지표를 기준 삼아서 만들어라. 출처가 있으면 더
믿음직스럽다." — 숫자를 만들어내지 말고 찾아오라는 요구였다.

## 조치

Simply Safe Dividends의 공개 스코어 밴드, Marc Lichtenfeld의 저서, 워런
버핏의 ROE 기준, 코퍼레이트 파이낸스 통설의 이자보상배율 코버넌트 관행,
D/E 업종 벤치마크 등을 실제로 조사해 5개 지표 전부를 출처 있는 숫자로
교체했다(전체 목록과 링크는 [decisions/14](../decisions/14-dividend-safety-score-formula.md) 참고).

**조사 과정에서 발견한 진짜 버그**: 부채비율 임계값(0.5~2.0배)을 조사하다가,
이 임계값들이 전부 **이자부담부채만** 분자로 쓸 때의 기준이라는 걸 알게
됐다. 그런데 애초에(그리고 `docs/decisions/12`에도) 짜여 있던 계산식은
`totalLiabilities ÷ totalShareholderEquity`(총부채÷자기자본)였다 —
매입채무 같은 영업부채까지 다 포함해서 이자부담부채보다 항상 훨씬 크다.
실제로 KO의 총부채 기준 비율은 2.193배였는데, 이걸 조사로 찾은 진짜 D/E
임계값(1.0~2.0배)에 그대로 적용했다면 코카콜라 같은 정상적인 배당
우량주도 "위험"으로 잘못 분류됐을 것이다. **사용자가 "근거를 찾아오라"고
요구하지 않았다면 이 계산식 결함은 절대 드러나지 않았을 것** — 원래 계획대로
임의 임계값을 썼다면 계산식이 틀려도 숫자가 "그럴듯하게" 나와서 아무도
의심하지 않았을 상황이다.

**수정**: 분자를 Alpha Vantage BALANCE_SHEET의 `shortLongTermDebtTotal`
(단기+장기 이자부담부채 합산 필드)로 교체했다.

## 검증

**실측값으로 재검증**: 잘못된 계산식으로 계산했다면 KO는 66점대(YELLOW)가
나왔을 것을, 수정된 계산식으로는 70점(GREEN)이 나왔다 — 이번 수정이
결과를 실제로 바꾸는 유의미한 정정이었음을 확인했다. 별도 Python
스크립트로 API 응답을 독립 재계산해 정확히 일치함도 확인.

**두 번째 종목으로 재검증**: 이 문서 작성 직후 JNJ 재무 데이터를 추가
수집해 API로 재확인했다 — 총점 100점(GREEN), 5개 지표 전부 만점 근처
(부채비율 0.59배, 이자보상배율 34.55배). KO보다 훨씬 보수적인 재무구조가
그대로 반영된 결과라 계산식이 종목마다 다른 실제 재무 상태를 제대로
구분해내고 있음을 추가로 확인했다.

**API 응답 구조**: 총점·밴드만 주지 않고 5개 지표 각각의 원본 값과
서브스코어를 같이 반환하도록 설계했다(`GET /api/tickers/{symbol}/safety-score`).
"합산 점수도 의미 있지만 지표 하나하나도 의미 있지 않냐"는 사용자
질문에서 나온 결정 — 기획서의 "1단계 신호등만 / 2단계 탭하면 지표별
노출"을 API 한 번으로 지원한다. React 프론트엔드(신호등 카드 + 탭하면
펼쳐지는 지표 5개)도 이 응답 구조를 그대로 소비하도록 만들고, 로컬에서
운영 DB에 접속해(SSH 터널) KO·JNJ 실측 응답으로 화면 로직을 검증했다.

## 다음/한계

- 이번 실측은 브랜드 풀 8종목 중 KO·JNJ 2종목만 마쳤다. Alpha Vantage
  무료 플랜이 하루 25콜(4콜/종목)로 제한돼 있어 나머지 종목은 여러
  날에 나눠 수집 중이다.
- 업종별 차등을 반영하지 않는다 — 유틸리티처럼 구조적으로 D/E가 높아도
  정상인 업종이 브랜드 풀에 들어오면 왜곡될 수 있다(`decisions/14` "남은
  위험" 참고).
- 가중치는 5개 지표 동일(각 20점)로 뒀다 — 다르게 줄 근거자료를 찾지
  못해서 균등하게 둔 소극적 선택이지, 최적이 검증된 건 아니다.
