# 미국 배당 원천징수 세금 계산 (US Dividend Withholding Tax)

PROJECT.md 5.5절. 배당 지급액에서 미국 원천징수 15%를 뗀 실수령액을
계산한다. 완전 신규 — 기존 어떤 지표에도 세금 로직이 없었다
(`docs/ai-defects` 조사에서 `Tax`/`Withholding`/`세금` 관련 코드 0건
확인).

## 0. 스코프

- **미국 원천징수 15%까지만 계산한다.** 금융소득종합과세(연간
  2,000만원 초과 시 합산 과세)는 계산하지 않고 고정 안내 문구로만
  처리한다 — 이유: 종합과세 여부 판정은 이 프로젝트가 추적하지 않는
  **포트폴리오 전체 보유 종목의 연간 합산 소득**이 필요한데, 사용자
  보유 수량·포트폴리오 모델 자체가 아직 없다(PROJECT.md 4.4절 "목표
  역산"과 마찬가지로 여유 시 기능). 근거 없이 임의로 확장하지 않는다.
- **이 지표가 다루는 통화는 USD뿐이다.** 프로젝트 유니버스가 전부
  미국 배당킹 종목이라 `Ticker.currency == "USD"`가 아닌 종목은
  스코프 밖으로 명시적으로 막는다(4절 예외 케이스) — 한국 주식
  15.4%와 혼동하지 말라는 CLAUDE.md 규칙을 "애초에 그 경로 자체를
  차단"하는 방식으로 지킨다.
- **한·미 조세조약상 국내 추가 납부는 없다**(PROJECT.md 5.5절) — 이
  계산이 곧 최종 실수령액이다. 원화 환산(5.6절, 환율)은 이 스펙의
  범위가 아니고 별도 스펙에서 다룬다 — 이 지표는 USD 그대로의
  세전/세후만 계산한다.
- **정기/특별배당 구분과 무관하게 전부 과세 대상이다** — IRS
  원천징수는 배당 유형(정기/특별)을 구분하지 않는다. 따라서 이
  지표는 [[special-dividend-disclosure]]와 달리 `REGULAR`/`SPECIAL`
  전체 지급 이력을 대상으로 한다.

## 1. 계산식

### 1.1 입력 변수

| 변수 | 정의 |
|---|---|
| `grossAmount` | `DividendPayment.amount` — 주당 세전 배당금(raw, 분할 미조정) |
| `US_WITHHOLDING_TAX_RATE` | `BigDecimal("0.15")` 상수 (CLAUDE.md 지정 이름 그대로) |

### 1.2 실수령액

```
netAmount = grossAmount * (1 - US_WITHHOLDING_TAX_RATE)
          = grossAmount * 0.85
```

- 분할 조정을 하지 않는다 — [[special-dividend-disclosure]]와 같은
  이유로, 이 지표는 "그 시점에 실제로 받은 주당 금액"을 다루는 것이지
  현재 주식 수 기준으로 정규화된 비교값이 아니다.
- `grossAmount * 0.85` 연산은 `MathContext.DECIMAL64`로 계산한다
  (프로젝트 전체 관례).

## 2. 기준 시점

- 특정 시점(`asOf`) 개념 없음 — [[special-dividend-disclosure]]와
  동일하게 **종목의 전체 지급 이력**을 한 번에 계산해서 보여주는
  목록형 지표다.
- 정렬 기준은 ex-dividend date 오름차순(프로젝트 전체 관례).

## 3. 반올림 방향

- `netAmount`는 최종 출력 직전에 **소수 2자리, `RoundingMode.HALF_UP`**로
  반올림한다.
- 이유: 이 값은 비율(%)이 아니라 **통화 금액**(주당 달러)이므로, 이
  프로젝트가 지금까지 %p 지표에 써온 반올림 자릿수(소수 2자리)를
  통화의 관례적 정밀도(달러의 센트 단위, 소수 2자리)에 그대로
  맞춘다 — 우연히 같은 자릿수지만 근거는 다르다.

## 4. 예외 케이스

| 상황 | 처리 |
|---|---|
| 티커 자체가 존재하지 않음 | `NoSuchElementException` — 기존 서비스들과 동일한 예외 패턴 |
| `Ticker.currency != "USD"` | `IllegalStateException` — "이 지표는 미국 원천징수만 계산하며 통화가 USD가 아닌 종목은 지원하지 않는다"는 메시지. 조용히 15%를 적용하지 않고 명시적으로 막는다(CLAUDE.md 세율 혼동 금지 원칙을 코드로 강제) |
| 지급 이력이 0건 | 에러 아님 — 빈 목록 반환 |
| 특별배당이 섞여 있음 | 정상 처리 — 0절대로 REGULAR/SPECIAL 구분 없이 전부 과세 대상으로 계산 |
| 연간 금융소득 2,000만원 초과(종합과세 대상 여부) | 계산하지 않음. API 응답에 고정 안내 문구 필드(`taxNotice`)를 추가해 "이 계산은 원천징수 15%까지만 반영하며, 연간 금융소득이 2,000만원을 초과하면 금융소득종합과세 대상이 될 수 있습니다" 같은 정적 문구를 항상 노출 — 사용자 결정 없이 PROJECT.md 5.5절 "안내 문구로 처리" 원문을 그대로 구현 |
| 원화 환산이 필요한 경우 | 이 지표의 범위 밖(0절) — [[exchange-rate-conversion]](5.6절, 미작성)의 책임 |

## 5. CLAUDE.md 정합성 체크

- ✅ `BigDecimal`만 사용, `double`/`float` 없음(ArchUnit 강제)
- ✅ 세금은 계산의 마지막 단계에서만 적용 — 이 지표 자체가 "마지막
  단계"이고, 다른 지표(TTM/CAGR/변동성 등)의 계산 파이프라인 안에
  세금을 끼워 넣지 않는다
- ✅ `US_WITHHOLDING_TAX_RATE` 이름을 정확히 그대로 사용, 한국
  15.4%와 혼동 불가(통화 체크로 아예 경로 차단)
- ✅ 서비스 계층은 DB만 읽음 — 외부 API 호출 없음
- ✅ 투자 판단/추천 문구 없음 — "세후 얼마"만 보여주고 투자 여부는
  말하지 않음
