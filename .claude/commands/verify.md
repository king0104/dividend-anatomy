# /verify — 손계산 대조

목적: 테스트가 통과한다는 것과 숫자가 실제로 맞다는 것은 다르다. 최소
1개는 사람이 직접 손으로 계산한 값과 대조해야 한다 (CLAUDE.md: "테스트
없는 계산 로직을 추가하지 않는다. 최소 1개는 손계산으로 검증한 값이어야
한다").

검증 대상: $ARGUMENTS

## 지켜야 할 것

- 대상 계산 로직과 그에 대응하는 테스트 클래스를 찾는다. 테스트가 없으면
  먼저 만들어야 한다고 알리고 중단한다 — `/verify`는 검증이지 테스트 작성
  대체가 아니다.
- 기존 테스트 케이스 중 손계산으로 검증된 게 있는지 확인한다. 주석이나
  테스트 이름에 "손계산", "hand-calculated" 같은 표시가 없으면, 실제로
  누가 손으로 계산해본 값인지 사용자에게 직접 묻는다 — AI가 계산기 역할로
  스스로 만든 기대값은 손계산이 아니다.
- 손계산 케이스가 없거나 부족하면:
  1. 간단한 입력값(라운드 넘버, 극단값 1개 포함)을 하나 고른다.
  2. 계산식을 단계별로 펼쳐서 사용자와 함께 손으로 계산한다 — 이 과정의
     각 단계를 텍스트로 보여준다 (중간값 생략하지 않는다).
  3. 그 결과를 새 테스트 케이스로 추가하고, 테스트 코드 주석에 손계산
     과정을 요약해 남긴다.
- 반올림 방향(`RoundingMode`)이 스펙(`docs/specs/`)과 실제 코드에서
  일치하는지 별도로 확인한다 — 반올림 차이는 assert 통과 여부만 봐서는
  안 잡힌다.
- 대조 결과 불일치가 발견되면 코드를 고치기 전에 `/defect`로 먼저 기록할지
  물어본다.
- 모든 대조가 끝나면 어떤 케이스를 손계산으로 확인했는지 요약해서
  보여준다 (커밋 메시지나 PR 설명에 쓸 수 있게).
