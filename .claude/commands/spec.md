# /spec — 지표 스펙 작성

목적: 스펙 없이 바로 구현하면 반올림 방향, 기준 시점 같은 애매한 지점을
AI가 임의로 정해버린다 (돈 계산에서는 이게 치명적이다). 구현 전에 반드시
아래 4가지를 문서로 확정한다.

대상 지표: $ARGUMENTS

## 지켜야 할 것

- `docs/specs/{지표명}.md` 파일을 새로 만든다. 이미 있으면 내용을 보여주고
  덮어쓸지 물어본다.
- 아래 4개 섹션은 **빈 칸으로 남기지 않는다.** 정보가 부족하면 추측해서
  채우지 말고, 사용자에게 직접 질문해서 채운다.
  1. **계산식** — 실제 수식 (변수명 정의 포함). "TTM 배당 합계를 종가로
     나눈다" 수준이 아니라, 어떤 필드를 어떤 순서로 계산하는지 명시.
  2. **기준 시점** — 가격은 어느 날짜 기준인가? 배당은 지급일/기준일/배당락일
     중 무엇을 쓰는가? CLAUDE.md의 T+1 규칙, 환율은 "배당 지급일 기준"
     원칙과 충돌하지 않는지 확인.
  3. **반올림 방향** — 소수 몇 자리에서, `RoundingMode`는 무엇을 쓰는가
     (`HALF_UP`인지 `HALF_EVEN`인지 등). 이유도 한 줄 남긴다.
  4. **예외 케이스** — 배당 이력이 없는 종목, 특별배당이 섞인 경우, 시계열에
     구멍이 있는 경우, 분할 전후 단위가 안 맞는 경우 등 이 지표에서 실제로
     발생 가능한 경우를 나열하고 각각 어떻게 처리할지 정한다.
- 스펙이 CLAUDE.md의 절대 규칙(BigDecimal, 서비스 계층 DB-only, 특별배당
  분리 등)과 충돌하는 부분이 있으면 구현 전에 먼저 지적한다.
- 스펙 작성이 끝나면, `docs/ai-predictions.md`에 이 지표 구현 중 AI가 틀릴
  만한 지점이 있는지 사용자와 함께 예측해서 추가할지 물어본다 (workflow.md
  2단계).
- 스펙 파일 작성 후 커밋하지 않는다 — 커밋은 구현이 끝나고 테스트가 통과한
  뒤 한 번에 한다 (workflow.md 참고).
