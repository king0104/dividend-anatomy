# /defect — 실패 순간 즉시 기록

목적: 실패 사례는 나중에 몰아서 쓰면 기억이 흐려진다. 방금 일어난 일을
바로 기록한다.

입력: $ARGUMENTS

## 지켜야 할 것

- 지금까지의 대화에서 실제로 있었던 실패 사례 하나를 특정한다. 여러 개가
  섞여 있으면 어떤 걸 기록할지 사용자에게 확인한다. `$ARGUMENTS`가 비어
  있으면 대화 맥락에서 가장 최근의 실패를 찾아 이거 맞는지 먼저 확인한다.
- `docs/ai-defects/` 안의 기존 파일들과 번호가 안 겹치게
  `{다음번호}-{짧은-영문-slug}.md` 파일을 새로 만든다 (예:
  `docs/ai-defects/01-archunit-event-inversion.md` 다음은 `02-...`).
- 기존 항목들과 같은 구조를 따른다:
  1. 제목 — 무엇이 실패했는지 한 줄
  2. **날짜**, **관련 커밋** (있으면 커밋 해시)
  3. **무슨 일이 있었나** — 실제로 벌어진 증상. 코드/명령/에러 메시지를
     그대로 인용.
  4. **왜 놓칠 뻔했나** — 왜 처음엔 못 알아챘는지, 어떤 착각이 있었는지.
  5. **어떻게 잡았나** — 무엇을 보고/시도해서 원인을 찾았는지.
  6. **어떻게 고쳤나** — 실제 수정 내용 (코드 diff 요약이나 스니펫).
  7. **교훈** — 다음에 비슷한 걸 피하려면 뭘 기억해야 하는지, 일반화 가능한
     규칙이면 CLAUDE.md에 추가할지도 물어본다.
- 추측이나 일반론으로 채우지 않는다 — 실제로 무슨 일이 있었는지 모르는
  부분은 사용자에게 물어본다.
- 작성 후 별도 커밋으로 남긴다 (다른 코드 변경과 섞지 않는다). 커밋 메시지엔
  `Catch:` 줄에 이 실패 요약을 넣는다.
